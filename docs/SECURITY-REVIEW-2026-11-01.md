# Статическая проверка после обнаружения Defender

Дополнение 2 ноября 2026: добавлен отдельный процесс сборки и сканирования в
GitHub Actions, описанный в [DEFENDER.md](DEFENDER.md). CI-скрипт скачивает
официальный компилятор Zig с проверкой закреплённого хеша и обновляет базы Defender. На
одноразовом github-hosted Windows-worker включает мониторинг и удаляет
предустановленные исключения сканирования. Это относится к CI-скриптам;
настройки защиты рабочего компьютера не менялись, сетевой клиент в приложение
не добавлен. Нижеследующий статический разбор выполнен до этих CI-изменений.

Дата: 1 ноября 2026. Объект: исходники Dark1C после 0.2.2, MinHook 1.3.4,
инструменты сборки. Это внутренняя проверка, не независимый аудит.

## Итог

Обнаружение Wacatac не признано ложным. Заблокированный EXE не запускался,
не восстанавливался из карантина и не пересобирался ради снятия обнаружения.
Из-за запрета чтения Defender не удалось получить хеш и проверить соответствие
этого EXE исходникам. Поэтому заключения о безопасности бинарника нет.

## Подтверждённое происхождение

- SHA-256 архива Zig 0.14.1 x86_64-windows совпадает с официальным индексом:
  `554f5378228923ffd558eac35e21af020c73789d87afeabf4bfd16f2e6feed2c`.
  Извлечённый zig.exe также совпадает с записью внутри этого архива:
  `1ddf230367e07738c4a769eae66c1db7469e37bd520e81c86356453d0db2b9fd`.
  Побайтово сверены все 14 673 файла извлечённого дистрибутива с архивом:
  отсутствующих и отличающихся файлов нет. Файлы не исполнялись при сравнении.
- Для повторно скачанного официального архива MinHook v1.3.4 SHA-256:
  `172708123daa0c98d20d3a980b16a50be14af243dc95dee6f79c24193ad010e4`.
  Сверены все 57 файлов: 27 текстовых совпадений, 30 отличаются только переводами
  строк; отсутствующих, дополнительных или отличающихся по содержимому файлов нет.
  Сравнение учитывает BOM как маркер кодировки.
- У локального csc.exe из .NET Framework 4.x проверка Authenticode вернула Valid,
  подписант — Microsoft Windows / Microsoft Corporation.

Официальные источники: [индекс Zig](https://ziglang.org/download/index.json),
[релиз MinHook](https://github.com/TsudaKageyu/minhook/releases/tag/v1.3.4).
Хеш архива подтверждает его содержимое, но сам по себе не проверяет будущие сборки.

## Что обнаружено в собственном коде

1. `src/Native.cs`, InjectCore: намеренная цепочка OpenProcess → VirtualAllocEx →
   WriteProcessMemory → CreateRemoteThread(LoadLibraryW). Это функциональность
   инъектора. Её связь с конкретной классификацией Defender — гипотеза, не вывод.
2. `src/Payload.cs`: встроенные DLL/PNG записываются в LOCALAPPDATA, проверяются
   SHA-256; `src/LiveWindow.cs` может по нажатию пользователя запросить runas.
   Загрузка DLL из доступного пользователю каталога в повышенный процесс требует
   отдельного рассмотрения границ доверия. Сам хеш не заменяет подпись издателя.
3. До правки RuntimeDirectory кешировал путь без повторной проверки; при отсутствии
   ресурсов допускался переход к соседней DLL. Исправлено в исходниках: отказ без
   встроенных ресурсов, повторная проверка, проверенный файловый дескриптор с
   FileShare.Read удерживается до завершения ожидания загрузчика. Это не полное
   устранение всех гонок и не гарантированная защита повышенного процесса.
4. Убрано ненужное право PROCESS_VM_READ при открытии процесса для инъекции.
5. Собственная DLL устанавливает перехваты Cairo и Win32/UxTheme внутри сеанса.
   OFF переключает поведение, не выгружает код. Это источник рисков сбоев,
   даже если вредоносного намерения нет.

При просмотре собственных C/C#/PowerShell исходников не обнаружены сетевые клиенты,
обратные соединения, кража паролей, чтение содержимого базы, автозапуск, изменение
антивируса или загрузка произвольного кода из сети. Сборка использует локальные
инструменты, зависимости уже включены. Поиск ключевых API дополняет чтение кода,
но не является доказательством отсутствия вредоносного поведения.

## Что осталось открытым

- Установить соответствие заблокированного бинарника исходникам в разрешённой
  среде анализа; на текущей машине чтение блокируется.
- Проверить воспроизводимость сборки. До этого побайтовая воспроизводимость
  не заявляется; отметки времени и параметры компоновщика могут влиять на результат.
- Пересмотреть поддержку повышенного режима, доступ к каталогу DLL и именованной
  разделяемой памяти; проверить подмену путей и гонки загрузчика.
- Провести независимую проверку и при необходимости отправить образец Microsoft
  через официальный портал. Никакие образцы или журналы не отправлялись.
- Проверить и протестировать правки загрузчика. После обнаружения полный EXE
  и тестовые инъекции не выполнялись; статус запуска остаётся приостановленным.
  Отдельные изменения оформления проверялись компиляцией графической библиотеки,
  а модель профиля — тестами в памяти без загрузчика и подключения к 1С.
